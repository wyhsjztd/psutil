## 1. 项目概述

本项目实现一个基于 `psutil` 的桌面系统监控程序，实时展示操作系统的：

- CPU 占用率（总体与每个逻辑处理器）
- 内存与交换文件使用情况
- 各磁盘分区使用率
- 网络收发速率
- 磁盘 I/O 读写速率
- 进程列表、Windows 服务、登录用户

界面布局参照 Windows 11 任务管理器「性能」页：左侧为指标导航卡片，右侧为实时曲线与统计数据。

## 2. 技术选型

| 技术 | 版本 | 选择理由 |
|---|---|---|
| Python | 3.10+ | psutil 原生支持，开发效率高 |
| psutil | 7.x | 跨平台系统信息库，覆盖 CPU / 内存 / 磁盘 / 网络 / 进程 |
| PySide6 | 6.8 | Qt 官方 Python 绑定，信号槽机制天然隔离采集线程与 UI 线程 |
| pyqtgraph | 0.13 | 基于 Qt 的实时绘图库，自带缩放、十字光标等交互 |
| unittest | 标准库 | 无需额外依赖，`python -m unittest` 即可运行 |

**为什么用 PySide6 而不是 Tkinter：**

Tkinter + matplotlib 在 1 Hz、60 点的场景下完全可用，本项目选择 PySide6 的原因不在性能，而在于：

1. `QThread` + `Signal/Slot` 提供语言级的跨线程通信保障，无需自行实现线程安全队列；
2. `pyqtgraph` 的 `PlotWidget` 自带交互能力，且与 Qt 布局体系一致；
3. QSS 样式表可低成本实现统一的深色主题；
4. 打包后为原生控件观感，与 Windows 11 视觉一致。

需要说明的是，pyqtgraph 默认使用 QPainter 光栅渲染，并非 OpenGL；本项目也未开启 `useOpenGL`，以避免在虚拟机、远程桌面等环境下出现驱动问题。

## 3. 系统架构

```
┌──────────────────────────────────────────────────────────────┐
│                          UI 线程                              │
│  MainWindow ── QStackedWidget ── 8 个页面                     │
│      ▲                  ▲                                    │
│      │ Signal(object)   │ Signal(object)                     │
├──────┼──────────────────┼────────────────────────────────────┤
│ SampleWorker(QThread)   │          ServiceWorker(QThread)    │
│   │                     │              │                     │
│   ▼                     │              ▼                     │
│ Collector ──────────────┘      psutil.win_service_iter()     │
│   │                                                          │
│   ▼                                  （WMI 逐条查询，较慢，   │
│ psutil API                            独立线程、30 秒一次）   │
│   │                                                          │
│   ▼                                                          │
│ engine.compute_rate / History / HysteresisAlarm（纯逻辑）     │
└──────────────────────────────────────────────────────────────┘
```

分层职责：

| 模块 | 职责 | 是否依赖 psutil / Qt |
|---|---|---|
| `models.py` | 冻结数据类，定义跨线程传输的快照结构 | 否 |
| `engine.py` | 速率差分、历史窗口、告警滞回、格式化 | 否（可单测） |
| `collector.py` | 调用 psutil，隔离异常，缓存分区列表 | 仅 psutil |
| `worker.py` | 采样线程，按固定间隔产生快照 | Qt |
| `services.py` | 服务枚举独立线程 | Qt + psutil |
| `ui/*` | 渲染，不直接调用 psutil | Qt |

**关键约束：UI 线程不调用 psutil，采集线程不触碰控件。** 二者只通过 `Signal(object)` 传递不可变的 `Snapshot`。

## 4. 指标定义

| 显示指标 | psutil API | 计算公式 | 单位 | 采样频率 |
|---|---|---|---|---|
| CPU 总利用率 | `cpu_percent(interval=None)` | psutil 内部两次调用差分 | % | 1 s |
| 每核利用率 | `cpu_percent(percpu=True)` | 同上 | % | 1 s |
| CPU 频率 | `cpu_freq().current` | 直接读取 | MHz | 1 s |
| 内存使用率 | `virtual_memory().percent` | `used / total` | % | 1 s |
| 交换文件 | `swap_memory()` | `used / total` | % / B | 1 s |
| 分区使用率 | `disk_usage(mount)` | `used / total` | % | 1 s（分区列表 30 s 刷新） |
| 网络接收速率 | `net_io_counters().bytes_recv` | `Δbytes / Δt` | B/s | 1 s |
| 网络发送速率 | 同上 `.bytes_sent` | `Δbytes / Δt` | B/s | 1 s |
| TCP 连接数 | `net_connections(kind="inet")` | `len(...)` | 个 | 5 s |
| 磁盘读速率 | `disk_io_counters(perdisk=True)` | `ΣΔread_bytes / Δt` | B/s | 1 s |
| 磁盘写速率 | 同上 | `ΣΔwrite_bytes / Δt` | B/s | 1 s |
| 进程列表 | `process_iter(["pid","name","cpu_percent","memory_percent"])` | 原值 ÷ 逻辑处理器数 | % | 3 s（独立线程） |
| 服务列表 | `win_service_iter()` | 直接读取 | — | 30 s |
| 登录用户 | `users()` | 直接读取 | — | 10 s |

**单位约定**：容量与吞吐量统一按 1 KB = 1024 B 换算；网络速率以字节为单位（B/s），不换算为比特率。

**进程 CPU 的口径**：psutil 的 `Process.cpu_percent()` 以单个核心为 100%，在多核机器上可超过 100%
（空闲时 `System Idle Process` 约为 N×100%）。任务管理器的口径是"全部逻辑处理器合计 = 100%"，
因此本程序将原值除以逻辑处理器数后再显示，两者才可直接对照。

## 5. 关键算法

### 5.1 速率差分

网络与磁盘 I/O 的 psutil 返回值是**自开机以来的累计计数器**，必须对两次采样做差分：

```
rate = (curr_value - prev_value) / (curr_time - prev_time)
```

实现见 `engine.compute_rate()`。以下四种情况返回 `None`，界面显示 `--`：

| 情况 | 判定 | 原因 |
|---|---|---|
| 首帧 | 无前值 | 没有可比较的基准 |
| 时间异常 | `dt <= 0` | 时钟跳变 |
| 间隔异常 | `abs(dt - nominal) > max(2×nominal, 0.5s)` | 暂停、改间隔、系统卡顿 |
| 计数器回绕 | `Δv < 0` | 系统重启或计数器归零 |

> 设计原则：**宁可不显示，也不显示错误的数值。**

### 5.2 基线重置

暂停恢复、修改采样间隔时，`SampleWorker` 显式调用 `Collector.reset_rates()`，
丢弃全部速率基线。恢复后的第一帧只记录基线、不产生速率，界面显示 `--`，
从根本上避免"暂停 30 秒后恢复，dt=30 导致巨大尖峰"的问题。

同一处还必须清掉 psutil 自身的缓存，否则会出现另一种隐蔽错误：

- `psutil.cpu_percent()` 的模块级 `_last_cpu_times`：不清的话，暂停 10 分钟后恢复，
  首帧返回的是这 10 分钟的平均值，而不是当前值；
- `process_iter` 的进程对象缓存：同理，进程的 `cpu_percent` 会跨越暂停区间。

因此 `reset_rates()` 会额外重新调用一次 `cpu_percent`，并调用 `process_iter.cache_clear()`。

这与 5.1 中的时间检查是两层机制：

- **显式重置**：处理已知事件（暂停、改间隔），确定性；
- **被动保护**：处理未知卡顿（GC、系统调度），兜底。

### 5.3 历史窗口与图表

- 历史缓存为 `deque(maxlen=3600)`，保存最近 1 小时的完整快照，同时作为 CSV 导出数据源；
- 图表 x 轴为**相对当前时刻的秒数**（`-60s … 0s`），窗口固定 60 秒；
- 绘图时按时间戳筛选窗口内的点，而不是取"最近 N 个点"，因此切换采样间隔后 x 轴语义不变；
- 切换采样间隔**不清空图表窗口**：x 轴是真实时间，新旧密度的点落在各自的时间位置上，
  Y 轴只按可见窗口内的点取量程。若清空窗口，切换后可见范围内只剩 0~1 个点，曲线会直接消失；
- 缺失值（`None`）转为 `NaN`，pyqtgraph 在该处断开曲线；暂停超过 2.5 倍采样间隔时同样插入断点，图上显示为空白而不是一条虚假的直线。

### 5.4 告警滞回

CPU 告警采用滞回 + 冷却：

- 利用率 ≥ 80% 触发；
- 降至 ≤ 75% 才解除；
- 两次通知间隔 ≥ 300 秒。

避免在阈值附近反复跳变导致告警刷屏。

## 6. 线程模型

| 线程 | 内容 | 停止方式 |
|---|---|---|
| UI 线程 | 渲染、交互 | — |
| `SampleWorker` | 1 秒采样性能指标 | `threading.Event` 中断 `wait`，`QThread.wait()` 收尾 |
| `ProcessWorker` | 3 秒全量遍历进程 | 同上 |
| `ServiceWorker` | 30 秒采集服务列表 | 同上 |

**为什么进程采集要独立线程：** Windows 上 `process_iter` 全量遍历约需 1 秒
（其中 `status`、`memory_info`、`num_threads` 每个字段都需额外系统调用，加上后耗时可达 4–5 秒）。
若放在 1 Hz 采样线程内，实际 `dt` 会远超名义间隔，网络与磁盘速率会被容差判定为异常而长期显示 `--`。
因此进程遍历走独立线程，主采样线程只读取加锁的缓存。

`SampleWorker` 内部使用可中断的 `Event.wait(interval)` 而非 `sleep`，
关闭窗口时 `stop()` 能在 50 ms 内响应，不会残留进程。

## 7. 性能优化

初版界面在 340+ 进程的机器上明显卡顿。实测定位到两处 UI 线程阻塞：

| 问题 | 实测 | 处理 |
|---|---|---|
| `QTableWidget` 每 3 秒重建 340×4 个单元格对象 | 单次最长 **6031 ms** | 改用 `QTableView + QAbstractTableModel`，刷新只做一次 `beginResetModel/endResetModel`，实测稳定在 **13 ms** |
| 服务表 328 行同样在 UI 线程重建 | 即使不在服务页也会执行 | 非当前页时只缓存数据，切换过去才渲染 |

其他调整：

- 进程遍历（Windows 上约 1 秒）放在独立线程；只在"进程"页保持 3 秒刷新，其他页面降为 10 秒，
  程序自身 CPU 占用由 13% 降至约 4%；
- 分区进度条与数值只在变化时调用 `setValue` / `setStyleSheet`，
  避免每帧触发控件子树重新计算样式；
- 状态栏、导航卡片等只更新当前可见页面。

优化后：UI 线程单帧耗时 p95 由 6031 ms 降至 14 ms，事件循环吞吐由 8.7k 提升到 115k 帧/秒，
1 秒采样间隔的实际抖动小于 100 ms。

## 8. 打包

使用 PyInstaller 打包为单文件、无控制台窗口的 exe：

```
python -m PyInstaller --onefile --windowed --name SysMon ^
  --icon assets\icon.ico --add-data "assets\icon.png;assets" main.py
```

资源路径通过 `sys._MEIPASS` 兼容源码运行与打包运行两种形态。

> 单文件模式启动时需解压运行库到临时目录，首次启动约 2–4 秒；
> 若更看重启动速度可改用 `--onedir`，产物为文件夹，启动约 1 秒。

## 9. 异常处理与降级

| 场景 | 处理 |
|---|---|
| 光驱空仓 / 移动盘已拔出 | `disk_usage` 抛错时跳过该分区 |
| 分区枚举遇到断连网络盘 | 分区列表缓存 30 秒，且先用 `opts` / `fstype` 过滤，不访问无效设备 |
| 网络计数器不可用 | 速率显示 `--`，不中断整帧采样 |
| 非管理员权限无法读取连接数 | 保持上一次的值 |
| 服务枚举失败 | 返回空列表，不影响性能页 |
| 单帧采集异常 | 跳过该帧，线程继续运行 |

异常项会记录在 `Snapshot.errors` 中，并在状态栏提示。

## 11. 已知限制

1. 仅在 Windows 11 上验证；服务页依赖 `win_service_iter`，其他平台为空。
2. 网络速率为所有网卡汇总值，包含回环、VPN 与虚拟机虚拟网卡。
3. 任务管理器的磁盘百分比是"活动时间占比"，与本程序的吞吐量（B/s）不是同一指标，不可直接比较。
4. 进程 CPU 占用为 3 秒采样区间内的平均值（且已按逻辑处理器数归一化），与任务管理器的瞬时值存在差异。
5. 服务列表刷新间隔 30 秒，状态变化存在延迟。
6. 不持久化历史数据，程序关闭后清空。
7. 采样精度受系统调度影响，高负载时实际间隔可能略大于设定值。
